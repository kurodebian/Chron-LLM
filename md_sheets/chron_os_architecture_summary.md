# Chron-OS / Chron-LLM アーキテクチャ設計 総集編

## 1. 開発基盤：インデックス駆動型ナビゲーション (`chapters_index.md`)
膨大な技術仕様（127章・約3.2 MB）をLLMのコンテキスト上限を圧迫せずに効率よくパース・探索するため、Pythonベースの軽量監査・インデックス機構を構築しました。

* **パース戦略**: マークダウンの **H1見出し（行頭の `# `）** のみを厳格に対象とし、ノイズとなるH2/H3や本文中のインライン言及を完全に排除。
* **監査機能 (`--coverage`)**: 
  * 全 127 章の整合性を自動監査。
  * 欠落（`STEP-5` や `STEP-104`）や、同一名称の重複（`STEP-1a / 1b`, `2a / 2b`, `3a / 3b`）を自動検出し、枝番を付与してマッピング。
* **効果**: 物理的にファイル分割を行وراずとも、各章の「ファイル名＋正確な行番号（Line）」を瞬時に特定し、ピンポイントの選択的読み込みを実現。

## 2. 基盤フェーズ①：決定論的状態機械とモデル検証（STEP-16 〜 18）
LLMの持つ「確率的・生成的な揺らぎ」を完全に飼い慣らし、システム側で決定論的な正当性を強制するためのアーキテクチャの土台です。

* **5軸直積の状態空間**:
  * 単一のステータスにフラグを詰め込むのを避け、`REVIEW_STATUS`, `VALIDATION_STATUS`, `CANDIDATE_STATUS`, `EVIDENCE_STATUS`, `EXECUTION_GATE` の5軸を直交させ、不正な組み合わせ（例：検証失敗なのにレビュー完了）を構造的に排除。
* **「ガード ＋ 抑止（禁止事項）」のペア定義**:
  * 各遷移（TR-01〜12）において「何をしてよいか」だけでなく、「何をしたら絶対にいけないか（例：検証器の障害を検証成功に偽装しない）」をセットで規範化。
* **LLMの役割の厳格な限定**:
  * LLMは「候補生成」と「批判（Critique）」のレイヤーに閉じ込め、正当性や遷移の裁定権限はすべて**決定的検証器（Deterministic Validator）**に集中。

## 3. 基盤フェーズ②：WAL・履歴回復・コミット原子性（STEP-23 〜 24）
単一ノードにおける耐久性と障害回復の心臓部であり、「推測によるデータ破壊」を防ぐための鉄の規律です。

* **「History = Canonical Truth」の原則**:
  * メモリ上の成功やLLMの出力ではなく、永続化された `Canonical History` こそが唯一の真実。
* **`IN_DOUBT` の温存と「不在証明」**:
  * 「記録が見つからない」からといって「Commitが存在しない」と短絡せず、ストレージ契約に基づく不存在証明ができない限りは勝手に結果を丸め込まず、安全に立ち止まる。
* **識別子の3層分離**:
  * トランザクション（`txid`）、履歴イベント（`event_id`）、WALレコード（`record_id`）のレイヤーを完全に分離し、正規化されたペイロード比較で冪等性を担保。
* **回復の決定論 ($Recover(H) = S$)**:
  * WALだけでなく、ストレージ契約やアルゴリズムのバージョンまで含めて固定された入力に対する決定論的な関数として回復を定義。

## 4. 拡張フェーズ③：分散合意・メンバーシップ・耐久性（STEP-75 〜 76）
単一ノードの堅牢なモデルをネットワーク越しに拡張し、スプリットブレインや偽りの成功を防ぐためのメタ・プロトコルです。

* **ミルestones（段階）の細分化**:
  * 「成功」や「ACK」という単一の概念を解体。到達可能性 $\neq$ クォーラム充足 $\neq$ 権限強制（STEP-75）、受信 $\neq$ ローカル永続化 $\neq$ 正準 Commit $\neq$ クライアント ACK（STEP-76）へと段階を徹底分解。
* **第一級の `UNKNOWN` 状態**:
  * ネットワーク異常やACK喪失時に、システムが勝手に二値化（成功／失敗）することを禁止し、不確実性をそのまま保持。
* **レプリカは「証拠」であって「権限」ではない**:
  * 複数ノードにデータがあることと、単一の正準 Commit 権限（Commit Authority）を持っていることは完全に独立しており、コピー数やダイジェストの一致だけで正当性を過信しない。

## 全体の総括とデザイン哲学

一連の仕様書群とインデックス解析から浮かび上がってきた Chron-OS / Chron-LLM の一貫した思想は、**「システムのあらゆるレイヤーにおいて、確率的推測や曖昧さを一切排除し、厳格な証拠（Evidence-bound）と不変条件（Invariants）に基づく決定論的制御を貫くこと」**にあります。
