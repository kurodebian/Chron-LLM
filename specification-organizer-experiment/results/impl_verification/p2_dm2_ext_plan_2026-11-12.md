## Code changes (tools/ only; minimal, tested)

The runner is reused, not forked. Four hard-coded points are parameterized,
each with the 127 path kept byte-identical:

1. load_units: also accept schema chron-llm/mdsheets-units-ext/1
   (rejects anything else exactly as before).
2. load_corpus(corpus_dir, file_names=None): file list derived from the
   units artifact's corpus_files; default (no artifact) stays the 3 P0 files.
3. gate_block(root, log_entries, gate_steps=...): CLI --gate-steps.
   Default stays STEP-1a + STEP-120 (127 contract unchanged).
   Extension gate anchors (deterministic, rationale below):
   STEP-125 (first ext unit), STEP-148 (largest ext unit, 66423 chars),
   STEP-218b (last ext unit, branch-letter id). Mirrors the 127 rationale
   (first + heaviest-at-risk) plus the ext-specific branch-letter id shape.
4. report set_check policy string: "127-unit" becomes artifact-count
   (cosmetic; only affects newly generated reports).

Verifier (tools/mdsheets_dm2_verify.py) becomes artifact-schema-aware on the
one 127-specific check: the P0 pass requires a non-empty unresolved_segments
block (1-74.md preamble preservation); the ext artifact records 0 unresolved
segments/headers (unitize_ext named checks), so for
chron-llm/mdsheets-units-ext/1 the verifier REQUIRES them empty (an
appearing unresolved segment is a FAIL, never silent). Declared segments are
still byte-checked against the live corpus in both cases. Corpus-untouched
check now covers the 4 ext files (same loop, artifact-driven).
All other verifier checks (reconstruction sha-pinning, exactly-one-OK log
pairing, disk-sha double match, validator authority, evidence substring/span,
digest) apply unchanged to the 99 units.

New tests tests/test_dm2_mdsheets_runner_ext.py (no model calls): ext schema
accept/reject, 99/99 sha-exact reconstruction from live bytes, ext corpus-file
loading, gate_block with custom anchors (PASS/FAIL/MISSING), plan=99 with
resume-skip, and verifier-ext behavior on an empty results dir (record_missing
FAILs present, unresolved_segments_empty check does NOT fire for ext schema —
MISSING_EVIDENCE != PASS direction).
