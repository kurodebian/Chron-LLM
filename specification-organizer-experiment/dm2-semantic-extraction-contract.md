# DM-2 Semantic Extraction

## SSOT: DM-2-0 / DM-2-1 / DM-2-2

**Status:** Draft for Formalization
**Scope:** Chron-LLM Specification Organizer
**Upstream:** A-1a-O / A-1a-V / A-1a-N
**Downstream:** DM-2-3 Extraction Record / DM-3 Causal Extraction

---

# 0. Normative Boundary

DM-2 operates exclusively on canonical units produced by A-1a-N.

A-1a is authoritative for document-unit boundaries.

DM-2 MUST NOT:

* split a canonical unit;
* merge canonical units;
* reorder canonical units;
* modify `unit_id`;
* modify `line_start`;
* modify `line_end`;
* modify `source_text`;
* introduce a new document span;
* remove a document span;
* reinterpret a boundary as a new boundary.

DM-2 answers:

> What semantic classification and semantic attributes are supported by this already-frozen unit?

DM-2 does NOT answer:

> Where should the unit begin or end?

That question belongs exclusively to A-1a.

# DM-2-0 Input Contract

## 1. Input Definition

The normative DM-2 input is one canonical A-1a unit.

Minimum canonical representation:

```json
{
  "unit_id": "u0001",
  "line_start": 13,
  "line_end": 23,
  "source_text": "exact text from document"
}
```

The input MUST originate from A-1a-N.

## 2. Input Field Semantics

### `unit_id`

The canonical identifier assigned by A-1a-N.

DM-2 MUST preserve it exactly.

### `line_start`

The canonical 1-based inclusive source-document start line.

DM-2 MUST preserve it exactly.

### `line_end`

The canonical 1-based inclusive source-document end line.

DM-2 MUST preserve it exactly.

### `source_text`

The exact source text regenerated by A-1a-N from the source document and canonical span.

DM-2 MUST treat it as immutable evidence.

DM-2 MUST NOT normalize, rewrite, summarize, correct, or otherwise modify it.

## 3. Cardinality

DM-2 operates on exactly one canonical unit per extraction record.

A DM-2 processing operation MAY process multiple units sequentially, but each unit remains an independent semantic extraction target.

Processing multiple units MUST NOT authorize:

* boundary merging;
* boundary splitting;
* span reassignment;
* cross-unit replacement.

## 4. Input Authority

The canonical A-1a unit is the authoritative structural input.

DM-2 MUST NOT reconstruct the unit from Markdown structure.

DM-2 MUST NOT derive a replacement span from headings, paragraphs, lists, whitespace, or formatting.

## 5. Invalid Input

If the supplied input does not satisfy the canonical A-1a unit contract, DM-2 MUST reject the input.

DM-2 MUST NOT repair an invalid canonical unit.

DM-2 MUST NOT silently discard invalid fields.

# DM-2-1 Semantic Unit Definition

## 1. Definition

A **DM-2 semantic unit** is the semantic interpretation assigned to one immutable A-1a canonical unit.

Formally:

```text
A-1a canonical unit
        ↓
semantic interpretation
        ↓
DM-2 semantic record
```

The semantic interpretation is derived from the content of `source_text`.

## 2. Semantic Scope

DM-2 MAY identify:

* the document-level semantic kind represented by the unit;
* semantic characteristics explicitly supported by the unit;
* semantic evidence contained in the unit;
* semantic ambiguity when the content does not support a unique classification.

DM-2 MUST distinguish observed textual evidence from inferred semantic interpretation.

## 3. Boundary Independence

The existence and extent of the semantic unit are inherited from A-1a.

Therefore:

```text
A-1a:
  boundary determination

DM-2:
  semantic interpretation of that boundary
```

DM-2 MUST NOT create a second segmentation layer.

## 4. No Causal Interpretation

DM-2 MUST NOT establish causal relationships.

DM-2 MUST NOT create:

* causal edges;
* dependency edges;
* trigger relations;
* mutation relations;
* transition relations;
* cause/effect assertions.

Such relations belong to the downstream causal extraction layer.

## 5. Semantic Evidence

A semantic classification MUST be supported by evidence contained in the canonical unit.

DM-2 MUST NOT invent semantic content absent from the unit.

When the text does not provide sufficient evidence for a classification, DM-2 MUST expose the uncertainty rather than silently selecting an unsupported classification.

# DM-2-2 Closed Vocabulary

## 1. Vocabulary Principle

DM-2 uses a closed vocabulary.

A semantic classification MUST be one of the formally permitted vocabulary values.

Free-form replacement labels are prohibited.

The initial vocabulary is:

```text
Heading
Requirement
Constraint
Definition
Description
Procedure
State
Event
Exception
Unclassified
```

## 2. Heading

`Heading` identifies a unit whose primary document-semantic function is a heading or section title.

`Heading` describes document semantic function.

It does not establish any causal or normative relation by itself.

## 3. Requirement

`Requirement` identifies a unit whose primary semantic function is to state something that is required to be satisfied, performed, provided, or maintained.

Classification as `Requirement` MUST be supported by the unit text.

## 4. Constraint

`Constraint` identifies a unit whose primary semantic function is to restrict what is permitted, possible, valid, or acceptable.

`Constraint` MUST NOT be inferred merely because a unit discusses implementation details.

## 5. Definition

`Definition` identifies a unit whose primary semantic function is to define a term, concept, object, rule, or other specification element.

## 6. Description

`Description` identifies a unit whose primary semantic function is explanatory or descriptive rather than prescribing a requirement, defining a term, or specifying a procedure.

## 7. Procedure

`Procedure` identifies a unit whose primary semantic function is to describe an ordered or operational method of performing a task.

A procedure remains one DM-2 semantic unit even when the canonical A-1a unit contains multiple procedural steps.

DM-2 MUST NOT split those steps into new units.

## 8. State

`State` identifies a unit whose primary semantic function is to describe a condition, status, configuration, or situation in which a system, component, process, or document-defined entity exists.

`State` is a semantic classification only.

It MUST NOT imply a transition or causal relationship.

## 9. Event

`Event` identifies a unit whose primary semantic function is to describe an occurrence, trigger, or externally/internal observable occurrence represented by the text.

`Event` classification MUST NOT itself establish a causal relationship.

Any causal relation involving an event belongs to DM-3.

## 10. Exception

`Exception` identifies a unit whose primary semantic function is to specify an exception, exceptional case, special handling condition, or deviation from a normal rule or procedure.

## 11. Unclassified

`Unclassified` identifies a unit for which the available evidence is insufficient to assign one of the defined semantic kinds with acceptable confidence.

`Unclassified` is an explicit classification.

It MUST NOT be used as a synonym for invalid input.

## 12. Closed-Vocabulary Rule

DM-2 MUST NOT emit a semantic kind outside:

```text
Heading
Requirement
Constraint
Definition
Description
Procedure
State
Event
Exception
Unclassified
```

If the text appears to require a category not represented in this vocabulary, DM-2 MUST NOT invent a new category.

The handling of such cases is governed by DM-2-5 Unknown / Ambiguous Handling.

---

# 3. Non-Goals of DM-2

The following are outside the DM-2-0 through DM-2-2 contract:

* causal graph construction;
* causal relation extraction;
* dependency graph construction;
* state-transition graph construction;
* authority graph construction;
* unit segmentation;
* unit merging;
* unit splitting;
* canonical source reconstruction;
* source correction;
* specification rewriting.

These responsibilities MUST NOT be introduced through semantic classification fields.

---

# 4. Authority Order

When interpreting a unit, the following authority order applies:

```text
A-1a canonical unit
        >
DM-2 semantic interpretation
        >
DM-3 causal interpretation
```

DM-2 MAY interpret the content of an A-1a unit.

DM-2 MUST NOT reinterpret the structural authority established by A-1a.

DM-3 MUST consume DM-2 output without redefining the A-1a boundary.
