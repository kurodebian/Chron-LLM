# Chron-OS / Chron-LLM Causal Kernel Architecture Document V1.1

## 1. 概要 (Overview)

本仕様は、将来的なChron-OSへの統合を見据えた独立サブシステム「Chron-LLM」の内部アーキテクチャ定義である。
**基本哲学：** 非決定論的で確率的な推論モジュール（LLM）の揺らぎや破綻を「構造的異常」として捉え、意味論（Semantics）をOSの意思決定から完全にパージする。決定論的な「因果（Causality）」のみで状態遷移と世界の歴史（WAL）を維持し、LLMをエミュレータのステートマシンのような決定論的な檻に封じ込める。

## 2. アーキテクチャの6フェーズ (Phase A - F)

データフローは完全な一方向パイプラインとして機能する。

* **Phase A (Schema):** 全事象を不変のEvent ABIとして構造体定義。
* **Phase B (WAL):** 意味を削ぎ落としたイベントと構造ラベルを1次元の単調増加ログとして永続化。
* **Phase C (Reducer):** WALからのログリプレイによる状態還元（論理状態の復元と物理コンテキストのリセット）。
* **Phase D (Lifting):** 1次元のWALから因果ネットワーク（DAG）を持ち上げ、クリーンな世界線を抽出・射影。
* **Phase E (Observation):** 意味を読まず、トポロジー（`:echo`, `:stagnation`, `:drift`, `:discontinuity`）のみで異常を観測。
* **Phase F (Control):** 決定論的アクション（`:commit`, `:discard`, `:retry`, `:retry-with-penalty`, `:abort`）へのルーティング。

## 3. Lamport clock と因果モデル

システム内のすべての状態変化は `clock`（Lamportクロック）のインクリメントを伴う。

* **イベントの発生 = 時間の進行:** LLMの正常な生成、構造的破綻（`:fault`）、および外部ツールの状態変化はすべて因果イベントとして扱われ、必ずクロックを進める。
* これにより、分散システムや非同期の外部I/O（ツール呼び出し等）における順序性が絶対的に保証される。

## 4. Graph / 世界線 / 再ハイドレーション

Graph上のエッジを「時間」と「因果」に厳密に分離する。

* **:temporal (時間的連続):** WAL上の物理的順序（Happens-Before）の証明。
* **:causal (論理的依存):** 意味的な世界線の継承。新系列（新 `causal-id`）の起点は、破綻直前の「最後の健全な対話ノード」にこのエッジを張る。
* **完全な記憶喪失（Amnesia）の徹底:** 破綻時、LLMのKVキャッシュは完全に焼却される。`:causal` エッジのみを逆行探索して `:fault` を構造的に枝刈りし、健全な履歴のみを一括ロード（Prefill）する。

## 5. Event ABI (V1.1 拡張版)

共通ヘッダとして `kind`, `index`, `clock`, `causal-id`, `timestamp` を保持する不変レコード。

* **異常の分離:**
* `event:structural-fault`: LLMの構造的破綻。旧系列の終端。
* `event:tool-fault`: 外部ツールの例外。原則としてLLMの文脈から除外（EXCLUDE）。


* **ツール介入の追跡（V1.1追加）:**
* `event:tool-call-start`
* `event:tool-call-timeout`
* `event:tool-call-abort`
* `event:tool-call-commit`



## 6. Partial Generation Rule (新規追加)

**生成ストリームのアトミック性（Atomic Commit Rule）**
生成中のトークン列は「不可分のトランザクション」として扱う。

* 生成ストリーム中に破綻（`:fault`）が発生した場合、その生成ストリーム全体を `:discard` とする。
* 破綻発生前の健全トークンであっても、WALには一切 `:commit` しない。
* WALへの `:commit` は「生成ストリームが構造破綻なく完了した場合」にのみ許可される。中途半端な状態（Dirty Read）は因果モデルに存在しないものとする。

## 7. Tool-call Causal Events (新規追加)

**外部副作用の中断イベントとクロックの扱い**
外部I/Oは本質的に非決定論的であるため、そのすべての状態遷移を因果として取り込む。

* ツール呼び出しの開始、タイムアウト、アボート、成功（コミット）の**すべて**を因果イベントとしてWALに記録する。
* これらのイベントはすべてLamportクロックを `+1` する。これにより、「外部システムが応答しなかった」という事実そのものが決定論的な歴史の一部として統合される。

## 8. Clean History Selection (新規追加)

**世界線の選択と封印のルール**
複数回の `:fault` が発生し、世界線が分岐した場合の「正史」の抽出を明文化する。

* 常に**現在アクティブな（最新の健全な）`causal-id**` の系列のみをPrefill（再ハイドレーション）の対象とする。
* `:fault` 発生時には即座に新しい `causal-id` を発行する。旧 `causal-id` の系列は「封印された世界線」としてWAL上に物理的には残るが、論理的なクリーンヒストリーの抽出からは完全に不可視化（枝刈り）される。

## 9. 不変量と安全性

V1.1の導入により、以下のシステム不変量が保証される。

1. **WALの単調性:** WALへの書き込みは常に追記のみであり、いかなる場合も過去のイベントは改竄・削除されない。
2. **生成の不可分性:** LLMの出力は「完全な成功」か「完全な非存在」の二値に収束する。
3. **文脈の清浄性:** LLMのKVキャッシュには、常に決定論的に検証された「健全な状態」のみがロードされる。

## 10. 実装フェーズへの写像指針

本仕様は、以下の技術スタックへ直接的にマッピングされることを想定する。

* **論理層 (Schema/Reducer/Lifting):** Common Lisp (`defstruct` / CLOS) を用い、シンボリックかつ型安全なイベント処理とDAGトポロジー計算を実装する。
* **物理層 (Observation/Control):** CFFIを経由し、`llama.cpp` 等の推論エンジンに対するKVキャッシュの明示的な破棄・Prefill制御（ステートセーブ／ロード機構）へバインディングする。
